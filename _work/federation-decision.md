## D1：为什么是网盘中继

R10 的目标是「项目在共享盘上，agent 各自在本地干活，盘只当传输带」。中继直接满足这句话：

- 每机仍用本地 `~/.infocenter`（或 `INFOCENTER_HOME`）。`mailbox.db` 不进网盘。
- 离线节点下次同步再取信，符合「至少一次 + 按 id 去重」。延迟等于网盘同步周期，R10 已接受秒到分钟级。
- 不要求对方进程常驻，也不要求每人安装 Tailscale。
- 服务继续只听 `127.0.0.1`、无鉴权。直连 HTTP 会把无鉴权端口暴露到 tailnet 或做端口转发，信任边界从「本机用户」扩到「能打到该端口的人」。这和现有安全边界冲突，不该绑进这一版。

Tailscale 以后可以做第二种传输。v1 的导出物是文件，不是 HTTP 调用；换传输不改消息语义。

中继在 B2 必须处理、这里只点名的失败：半截文件、网盘冲突副本、乱序、重复导入。导入只认完整 JSON，按 message id 幂等；冲突副本文件名忽略。

## D2：名字怎么分

今天 `normalize_name` 已允许点，且会折成小写：`robin.grok`、`a.b.c`、`robin.`、`节点.名字` 都能过；`..`、以点开头、超过 64 位不能过。点目前没有结构。两家都叫 `cursor`，导入时会合成同一个 agent。

建议规则：

- 本地身份继续是裸名（`grok`），不含点。现有信、守护、config 不改。
- 配置了本机 `node` 之后，线上身份是 `<node>.<裸名>`，**恰好一个点**。两段各自沿用现有字符集，但段内不再含点。整串仍必须能通过现有 `normalize_name`（≤64）。
- 裸名 `grok` 与 `robin.grok` 是两个 agent。发给裸名的信留在本机，不导出。
- `*` 仍只展开本机名单，不跨节点广播。收件人里带其他节点的名字才导出；同一封信可以本地投递一部分、导出一部分。
- 多点名字（`a.b.c`）和点在末尾不表示联邦身份，避免和任意历史名字撞车。

`store.py` 归 cursor。冻结后若要把「本地名不含点 / 线上名恰好一点」收进 `normalize_name`，我发 diff，不直接改。
